# Redrawing an existing diagram

Read this when the user supplied a diagram: an image, screenshot or export under `context/uploads/`. The picture is the spec. The `match` style points here.

A diagram the user supplies ("create an architecture based on this image", a whiteboard photo, a Visio/LakeDraw/Lucid export under `context/uploads/`) is the most specific instruction there is. **Reproduce its representation; don't reinterpret it** — the same boxes with their text, the same groupings, the same connections with their direction and labels, the same overall arrangement. It is not a pixel clone: route lines, align and space things however reads cleanly. The slide rules in SKILL.md and `compose.md` (theme, grid, text budget, the standard flow) do not apply — the picture already made those choices.

1. **Inventory before writing.** Open the image (crop sections if it is large) and list every box, every line (both ends, solid/dashed, colour, its label), every group boundary, and each box's centre in image pixels. Text is taken as drawn; where the source ellipsizes, keep what it shows.
2. **Each drawn box is a `type:"card"`** reproducing what it shows: `title` (with any "[CURRENT]"-style prefix), `icon` (a NAMED product — LakeWatch, CustomerLake, Snowflake — gets its own mark: `grep -i <name> reference/icons.tsv` before anything else; only an unnamed concept takes the closest match from the icon bank in `component-catalog.md`, and a `lucide:` glyph is the last resort, never for a product that has a mark), `badge` (a corner pill), `accent` (its border colour), and a **`body` in HTML** for everything under the header, laid out like the source: e.g. `<b>Lead line</b><br><span style="color:#64748b">Secondary description</span><div style="border:1px solid #94a3b8;border-radius:6px;padding:2px 6px;margin-top:4px"><b>Key</b> value</div><span style="background:#e2e8f0;border-radius:4px;padding:1px 6px;font-size:11px">TAG</span>`. A box with only a name → a card with no `body`. Don't substitute a catalog tile, a composite or a bare icon for a drawn card. A bespoke element no card or component fits (a metric strip, a small table, a custom legend) is an `html` block at its drawn place and size — see the html block in `containers-and-annotations.md`.
3. **Keep the arrangement.** What sits left/right/above/below what stays that way, rows stay rows, groups stay together. Build it from containers first: a row of drawn cards is a `row` container, a stack is a `column`, a grid is `layout: "grid"` with `cols`, and a shared line across containers is a `track`. Where the picture has no clear row, column or box, place a node with `at` (its offset from the parent's content corner) instead: give every node `at` = its image centre × ONE scale factor, and every box `size` = its drawn size × the same factor. **Take the scale from the text, not the boxes:** measure a typical label's height in the image (≈ its font size in px) and use `scale = 16 / that`, so text keeps the proportion it has in the picture (dense slides would otherwise come out with tiny text in big boxes). Then tidy freely (snap near-aligned cards onto one line, even out gaps).
4. **Each drawn line is an edge** in the same direction, with its `label` and the arrowheads it shows (`arrow:"end"` / `"both"` / `"none"` — set it explicitly; the default draws none on a plain edge). Keep `dashed` and `color` where they carry meaning (current vs proposed, a legend); routing is yours — pick the handles that read cleanly. A floating label belongs to the nearest line of the same colour. Edge labels default to 11px; set the tab's `options.edgeLabelSize` (usually 14–16) so they read at the source's proportion.
5. **A drawn box that contains smaller boxes** (a service with its components inside, a lifecycle stage with its tools under a pictogram) is a `box` with `title` (and `titlePos` matching where the picture puts it) whose `children` are one card per inner box, plus a `logo` for a pictogram — never one card with the inner names as its summary. Lines attach to whichever one they touch in the picture: the outer box or an inner card.
6. **Each group boundary is a `box`** whose `children` are exactly the cards inside it, with its `title`, `subtitle` (secondary header lines), `badge`, and `style` (`borderStyle:"dashed"`, colours).
7. **Add nothing the image doesn't draw** — no persona, Genie One, governance bar or platform banner — and drop nothing. Use `"theme":"technical"` and the closest `aspect`.
8. **Render, then compare section by section** against the source (same crops) and fix what differs: missing or cut-off text, wrong colour, a card out of place, a line on the wrong side. Then **count**: cards, edges and groups must match the inventory; record any deliberate difference in `story`.

Unreadable text: write your best reading and note it in that node's `ai_reasoning`. Depart from the drawing only where the user asks ("…but swap the sync tool for Lakeflow Connect", "make it a slide"), and only by what they asked.
