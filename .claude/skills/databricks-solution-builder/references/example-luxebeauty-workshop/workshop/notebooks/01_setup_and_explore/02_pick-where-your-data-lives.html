On Databricks, data lives in Unity Catalog — the governance layer over everything. At the top is your metastore (one per region), and inside it data nests in three levels:

  • Catalog — the top-level container, like a drive.
  • Schema — a folder of tables. Your project lives here.
  • Table — the data itself.

Everything you build in this workshop lands under one catalog.schema that you choose — a table's full name is catalog.schema.table. Browse everything you can see in Catalog Explorer in the left sidebar.

You need a catalog before you can start. This workshop creates a schema, but it cannot create the catalog above it — so you need one existing catalog where you hold the CREATE SCHEMA privilege. If you're not sure which one that is, ask first and let Genie Code find out:

Ask Genie Code

Which catalogs can I create a new schema in? List them with the privileges I have, so I can pick one.

Then pick one and have Genie Code set up your workspace inside it:

Ask Genie Code

Build this project in catalog <your-catalog>, schema <your-schema>. Create that schema if it doesn't exist, and make it the default for this notebook so everything I build lands there.

💡 Name both explicitly. If you just say "the catalog we agreed on," the Assistant may fall back to the workspace's default catalog and build your whole project somewhere you didn't intend. Spell out catalog.schema once, here.

💡 Genie Code will write and run the CREATE SCHEMA / USE SQL for you and define CATALOG / SCHEMA — the next cells reuse those.

✅ Confirm: SELECT current_catalog(), current_schema() returns what you asked for. Everything downstream assumes it.
