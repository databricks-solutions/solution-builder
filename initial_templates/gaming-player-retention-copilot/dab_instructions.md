# Deploying the Hollowspire Live-Ops Console (DAB)

Everything is parameterized in `databricks.yml`: `catalog`, `schema`, `warehouse_id`, `workspace_folder`, `app_name`,
`lakebase_project_slug` / `lakebase_branch_id` / `lakebase_database` / `lakebase_owner_role` / `lakebase_database_id`.

Targets:
- `default` (portable, the default target) — no pinned host; see "Deploy to your own workspace" below.

What each step does (nothing is created by hand):
1. `bundle deploy` builds the app (`app/scripts/build-app.sh`: npm install, deterministic Drizzle baseline, server + client
   build), uploads the bundle, and creates the Lakebase database, the AI/BI dashboard, the agent-traces MLflow experiment,
   the app (compute stopped; its env lives in `apps.liveops_app.config`, no `app.yaml`) and the setup job.
2. The setup job: `generate_data` (schema + synthetic telemetry, fixed calendar as of 2026-09-27) → `chat_toxicity`
   (`ai_classify` + `ai_analyze_sentiment` on the warehouse) → `train_models` (XGBoost churn + LTV, UC `@champion` — a new
   model version per run, SHAP → `churn_scores`, `gold_risk_segments`) → `deploy_genie` (created or updated by exact title)
   + `grant_app_uc` (SELECT on the schema, MODIFY on `liveops_schedule` for the app SP) → `export_resources` (Genie CAN_RUN
   for the app SP; writes `<catalog>.<schema>.demo_resources`).
3. `bundle run liveops_app` deploys the source and starts the app. At boot it reads the Genie space id from
   `demo_resources` and mirrors the at-risk segments from Delta into Lakebase.

The header's **Reset the demo** (`POST /api/admin/reset`) re-syncs the Lakebase mirror and clears `liveops_schedule`.

Redeploying against an existing Lakebase database is safe: `app/drizzle/` is generated by `scripts/db-generate.js` with a
pinned baseline (`0000_init`, fixed `when`), so the migration identity never changes for an unchanged schema.

## Deploy to your own workspace — portable `default` target

`default` is the bundle's default target and pins **no host**: it deploys to whatever workspace `-p <profile>` points at
(forks, Solution Builder "Download DAB"). Bundle files, dashboard, Genie space and experiments go under
`/Workspace/Users/<you>/gaming-player-retention-copilot` (`--var workspace_folder=…` to change).

- **Required:** `--var warehouse_id=<sql-warehouse-id>` (no default — validate/deploy fail without it).
- Usually overridden: `catalog` / `schema` (default `gaming.player_retention_copilot`; the catalog must exist and you need CREATE SCHEMA on it),
  `app_name` (must be unique in the workspace).
- Lakebase: the bundle creates the app database in an **existing** Lakebase (autoscaling) project, `lakebase_project_slug` (branch `lakebase_branch_id`, default `production`), owned by the Postgres role `lakebase_owner_role` (a GROUP role for the workspace `admins` group: `databricks postgres create-role projects/<project>/branches/production --role-id admins --json '{"spec":{"identity_type":"GROUP","postgres_role":"admins","auth_method":"LAKEBASE_OAUTH_V1"}}'`). Pass `--var lakebase_project_slug=… --var lakebase_owner_role=…` if yours differ.

```bash
# Variables resolve per command, so set them once for the shell (or pass the same --var's to all three commands):
export BUNDLE_VAR_warehouse_id=<sql-warehouse-id>                 # required
export BUNDLE_VAR_catalog=<catalog> BUNDLE_VAR_schema=<schema>    # optional
export BUNDLE_VAR_lakebase_project_slug=<project> BUNDLE_VAR_lakebase_owner_role=<role-id>
databricks bundle deploy -p <profile>
databricks bundle run player_retention_setup -p <profile>
databricks bundle run liveops_app -p <profile>
```
One-line equivalent: `databricks bundle deploy -p <profile> --var warehouse_id=<id> [--var catalog=<catalog> --var schema=<schema> --var lakebase_project_slug=<project> --var lakebase_owner_role=<role-id>]`
(same `--var`'s on each `bundle run`).

Local run: `cd app && cp .env.template .env` (PGHOST etc., DEMO_CATALOG/DEMO_SCHEMA; GENIE_SPACE_ID optional — read from
`demo_resources`), then `DATABRICKS_CONFIG_PROFILE=<p> ./start.sh` → http://localhost:8826. Point local runs at a separate
database: the deployed app's service principal owns the `app` schema in the bundle's database.

Local data build without the job (Python 3.12 venv with databricks-connect, numpy, pandas, xgboost, scikit-learn,
mlflow[databricks], databricks-sdk):
`python data_generation/generate_data.py --catalog <c> --schema <s>`,
`python src/deploy/run_sql_on_warehouse.py --catalog <c> --schema <s> --warehouse_id <wh> --sql_file src/ai/chat_toxicity.sql`,
`python src/ml/train_models.py --catalog <c> --schema <s> --experiment <path>`,
`python src/deploy/deploy_genie.py --catalog <c> --schema <s> --warehouse_id <wh> --parent_path <folder>`.
