# Deploy this demo (DAB)

Everything is parameterized in `databricks.yml`: `catalog`, `schema`, `warehouse_id`, `workspace_folder`, `app_name`,
`lakebase_project_slug` / `lakebase_branch_id` / `lakebase_database_id` / `lakebase_database` / `lakebase_owner_role`.

Targets:
- `default` (portable, the default target) — no pinned host; see "Deploy to your own workspace" below.

Nothing is wired by hand. The bundle creates the Lakebase database, the AI/BI dashboard, the app (command +
env in `config`, no `app.yaml`), the agent-traces MLflow experiment and the setup job. The job creates the schema, the
data, the UC model, the gold tables + metric view, the Genie agent (gold tables + the policy-docs volume, waits for its index), grants the app's service
principal, and writes the resolved IDs to `<catalog>.<schema>.demo_resources` — the app reads the Genie agent id
from there at boot (`app/server/services/resources.ts`).

## Deploy to your own workspace — portable `default` target

`default` is the bundle's default target and pins **no host**: it deploys to whatever workspace `-p <profile>` points at
(forks, Solution Builder "Download DAB"). Bundle files, dashboard, Genie space and experiments go under
`/Workspace/Users/<you>/cpg-trade-promotion-roi` (`--var workspace_folder=…` to change).

- **Required:** `--var warehouse_id=<sql-warehouse-id>` (no default — validate/deploy fail without it).
- Usually overridden: `catalog` / `schema` (default `retail_consumer_goods.trade_promotion_roi`; the catalog must exist and you need CREATE SCHEMA on it),
  `app_name` (must be unique in the workspace).
- Lakebase: the bundle creates the app database in an **existing** Lakebase (autoscaling) project, `lakebase_project_slug` (branch `lakebase_branch_id`, default `production`), owned by the Postgres role `lakebase_owner_role` (a GROUP role for the workspace `admins` group: `databricks postgres create-role projects/<project>/branches/production --role-id admins --json '{"spec":{"identity_type":"GROUP","postgres_role":"admins","auth_method":"LAKEBASE_OAUTH_V1"}}'`). Pass `--var lakebase_project_slug=… --var lakebase_owner_role=…` if yours differ.

```bash
# Variables resolve per command, so set them once for the shell (or pass the same --var's to all three commands):
export BUNDLE_VAR_warehouse_id=<sql-warehouse-id>                 # required
export BUNDLE_VAR_catalog=<catalog> BUNDLE_VAR_schema=<schema>    # optional
export BUNDLE_VAR_lakebase_project_slug=<project> BUNDLE_VAR_lakebase_owner_role=<role-id>
databricks bundle deploy -p <profile>
databricks bundle run trade_promo_setup -p <profile>
databricks bundle run trade_promo_app -p <profile>
```
One-line equivalent: `databricks bundle deploy -p <profile> --var warehouse_id=<id> [--var catalog=<catalog> --var schema=<schema> --var lakebase_project_slug=<project> --var lakebase_owner_role=<role-id>]`
(same `--var`'s on each `bundle run`).

Prereqs: Databricks CLI ≥ 1.10, Node 22 (the bundle builds the app), a serverless SQL warehouse, CREATE SCHEMA on the catalog, the `databricks-gpt-5-4` serving endpoint (or change `agentModel` in `app/config/app.json`).

Notes
- The dashboard JSON datasets are **schema-less**; `dataset_catalog` / `dataset_schema` rebind them.
- `genie/genie_space.json` is committed with `retail_consumer_goods.trade_promotion_roi`; `deploy_genie` rewrites
  that qualifier to your catalog/schema and adds the `trade_policy_docs` volume. The Genie agent ("Crestwood - Trade
  Promotion ROI") is looked up by name + catalog.schema, so re-running the job updates it in place.
- Data is generated **relative to "now"** (seed 42): the history ends last week and the plan covers the next 13
  weeks. Re-run `trade_promo_setup` before an important demo so the plan is still in the future, then click
  **Reset the demo** in the app header (or `POST /api/admin/reset`: re-syncs the Lakebase mirror, clears conversations
  and decisions).
- **Drizzle migrations are a build artifact** (`app/drizzle/`, regenerated by `build-app.sh` with the pinned
  `0000_init` baseline) — a rebuild against the existing database is a no-op as long as `server/db/schema.ts`
  is unchanged.
- Local dev: copy `app/.env.template` → `app/.env`, fill it (DEMO_CATALOG / DEMO_SCHEMA, warehouse, Lakebase PG*),
  `DATABRICKS_CONFIG_PROFILE=<profile> DATABRICKS_APP_PORT=8803 ./app/start.sh`. Use a separate database: the deployed
  app's service principal owns the `app` schema in the bundle's database.
